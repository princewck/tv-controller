# 旧协议测试适配器与新版电视源码

本目录有两部分：`server/` 保留旧 Node 服务，供兼容性回归测试使用；`android-webview/` 保存新版原生电视客户端。生产每日额度服务在 `../cloud/`。它们不能仅凭目录相邻就混用协议。公网应用部署与真实电视验收尚未完成。

## 旧 Node 测试服务

本节只描述 `server/`，不描述新版 APK 的规则。旧“阶段额度”是一次观看过程按学习挑战分阶段发放的时长；它与按北京时间自然日累计的每日额度是两个约束。

使用 Node 24.13 至 24.x，在本目录运行 `npm ci --ignore-scripts`。服务端回归命令为 `node --test test/{mobile,policy,tenancy,http,store,admin,learning-display}.test.mjs`；原生及浏览器测试另需对应环境。

`GET /admin/mobile_capabilities` 返回旧适配器支持的移动端能力。`POST /admin/control?device=设备标识` 接受 `paused` 布尔值和 UUID `request_id`；需要家庭会话、Origin 与 CSRF。暂停按设备生效，重复请求不增加版本。暂停优先于临时额度；解除暂停后，旧阶段额度、每日额度与休息时段仍生效。

旧适配器可增加 `daily_limit_seconds`，范围 60 至 86400 秒。未提供该字段时保留旧阶段规则；临时额度可以额外放行。旧客户端不发送执行回执，故服务接受指令不能证明电视已停止播放。

`server/` 与旧网页模板仍使用示例域名 `tv.example.com`，不能直接用于生产。测试域名 `tv.chengkai.wang` 当前是否支持新版协议，必须按技能中的协议检查确定，不能从域名推断。

## 新版原生电视客户端

新版 APK 已实现每日额度、休息时段、按设备暂停、执行回执、缓存规则及离线计时补传；不运行旧服务的学习挑战流程。源码与签名构建存在不代表实机已验收，兼容型号与真实播放、离线、自启及完整重启仍需逐项验证。

规则缓存不因断网自动失效，会持续沿用最后收到的规则；离线时手机无法下发新规则。客户端按北京时间在跨日时使用新的本地每日计数，重启后保留缓存规则和当日计数。时段判断依赖电视本地时钟与最近一次服务时间偏移；必要权限关闭、服务被强行停止或设备时钟异常可能影响执行。客户端最多补传最近两天的记录，不能承诺长时间离线后的完整历史。

新版 Android 的 Debug／Release 构建、签名与 ZIP 打包命令见[开发与候选发布](../docs/DEVELOPMENT.md#通用电视-apk)。

## 交给 Agent 安装

完整安装步骤在 `family-tv-ios/` 内的[安装技能](../distribution/family-tv-setup/SKILL.md)，并打包成带版本号的 ZIP。Agent 下载后先读 `SKILL.md`，再依安装参考、兼容性参考及辅助脚本完成工作。包内清单固定 APK 版本、SHA-256 和签名指纹，不为每台电视编译。

手机只展示四步引导。实际验收须验证播放拦截与恢复、权限、新心跳、关闭电视端 ADB，并由家长执行真正的系统重启。只有手机针对本次设备的全部检查通过并完成重启后的复测，才可宣布配置完成。
